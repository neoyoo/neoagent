# neoagent v3.1 Cross Review

日期: 2026-04-11

## 严重（必须修复）

- `Session.fork()` 只浅拷贝 `messages`，但 `Message`/`ToolUseBlock`/`ToolCall.input` 都是可变对象，所以 fork 后两个 session 仍会共享消息内部状态。见 `neoagent/session.py:50` 和 `neoagent/core/types.py:13`。这会导致子 session 修改 tool input 或 content block 时污染父 session，直接破坏 Multi-Agent 隔离。建议至少深拷 `messages`，或者把 message/block model 设为 frozen。

```python
def fork(self, new_id: str | None = None) -> "Session":
    now = datetime.now(timezone.utc).replace(tzinfo=None)
    return Session(
        id=new_id or str(uuid.uuid4()),
        messages=copy.deepcopy(self.messages),
        state=copy.deepcopy(self.state),
        created_at=now,
        updated_at=now,
    )
```

- `JsonFileStorage` 对 `session_id` 没有做路径约束，`save/load/delete` 都可能通过 `../` 逃逸出 session 目录。见 `neoagent/session.py:74-92`。这是明确的文件系统越界写/删风险，严重程度和之前 memory filename 问题一样。建议像 `MemoryStore` 一样做 containment check。

```python
def _path(self, session_id: str) -> Path:
    path = (self._base_dir / f"{session_id}.json").resolve()
    if not path.is_relative_to(self._base_dir.resolve()):
        raise ValueError(f"Invalid session id: {session_id!r}")
    return path
```

- 仍有跨 session 漏出的运行态没有搬进 `SessionState`：`ContextCompressor._consecutive_failures` 还挂在实例上。见 `neoagent/core/compress.py:52-55`。一个 session 连续压缩失败 3 次后，另一个全新 session 会直接走 truncation fallback，这是 session correctness 破坏，不只是风格问题。建议把它也迁入 `SessionState`。

```python
@dataclass
class SessionState:
    previous_summary: str | None = None
    compression_failures: int = 0
    ...
```

## 重要（应该修复）

- `Event` 虽然是 `frozen dataclass`，但核心字段仍然是可变对象，导致“不可变事件”是假的。见 `neoagent/events.py:40-43`、`neoagent/events.py:21-24`。更糟的是 `ToolExecutor` 直接把 `call.input` 原样塞进事件，handler 可在校验前篡改实际执行入参。见 `neoagent/tools/executor.py:69-76`。建议事件字段改为不可变结构，至少对 dict 做深拷贝后再冻结。

```python
from types import MappingProxyType

payload = MappingProxyType(copy.deepcopy(call.input))
self._bus.emit(ToolCallEvent(name=call.name, input_data=payload, call_id=call.id))
```

- `QueryLoop` 构造上允许 `tool_executor=None`，但只要模型返回 tool call，就会在运行时崩溃。见 `neoagent/core/loop.py:31` 和 `neoagent/core/loop.py:143`。这和“向后兼容 list[Message]”无关，是 API 合同不完整。建议在构造时强制要求 executor，或者在 tool path 上 fail-fast 抛出清晰错误。

```python
if self._executor is None:
    raise RuntimeError("QueryLoop requires ToolExecutor when tools are enabled")
```

- `BashTool` 的安全模型仍然不是可信边界。`bash --restricted` 只限制 shell 内建行为，但完全挡不住通过普通二进制逃逸；本地验证里 `awk 'BEGIN{system("echo awk_escape")}'` 和 `find ... -exec ...` 都能执行。实现见 `neoagent/tools/builtin/bash.py:77-85`。所以这块只能算“降低误操作风险”，不能算“安全执行”。建议把文档和命名说清楚，或继续收口到 capability-bounded runner。

- `BashTool` 的 timeout 只 kill 了顶层 `bash` 进程，不能可靠清理其子进程树。见 `neoagent/tools/builtin/bash.py:87-95`。对 pipeline、后台任务、`find -exec` 这种情况，孙进程可能残留。建议单独起 process group，并在超时时 killpg。

```python
proc = await asyncio.create_subprocess_exec(..., start_new_session=True)
...
os.killpg(proc.pid, signal.SIGKILL)
await proc.wait()
```

- EventBus 事件面并不完整：`MemoryExtractEvent`、`SkillChangeEvent`、`CompressFallbackEvent` 定义了，但当前没有任何 emitter。见 `neoagent/events.py:70-100` 以及全局搜索结果。`ObserverSubscriber` 已经为它们写了映射，但链路实际上是空的。这会让外部订阅者误判事件语义已经稳定。建议要么补 emit，要么删掉未落地事件。

- `NeoAgent.run(messages, session=existing)` 会替换 session 的消息列表，但保留旧 `SessionState`。见 `neoagent/agent.py:107-119`。这意味着你可以把一段全新对话塞进一个已有 summary/token/memory baseline 的 session，得到交叉污染的状态。这对 v3.2 Multi-Agent/session resume 都是危险 API。建议禁止同时传 `messages` 和“已有非空 session”，或在替换消息时显式 reset state。

- `ObserverSubscriber` 对 memory 事件的映射丢掉了 trigger 语义。见 `neoagent/observe_subscriber.py:52-56`。`MemoryExtractEvent(triggered=True, tool_calls, token_delta, items_stored=0)` 会被当成“extract_done”而不是“trigger”。如果以后真把 trigger/done/skip 三阶段发出来，这个适配器会立刻失真。

## 代码质量（应该改进）

- `subscribe_all()` 依赖硬编码 `_ALL_EVENT_TYPES`，新增事件时很容易漏改。见 `neoagent/events.py:105-138`。当前做法简单，但对 v3.2 hooks 扩展不稳。建议基于 `Event.__subclasses__()` 递归收集，或者让事件声明自动注册。

- `MemoryManager` 和 `ContextCompressor` 对 `session_state` 的策略不一致：都接受 `None`，但一个是“静默 no-op”，一个是“仍正常工作但失去跨轮态”。见 `neoagent/memory/manager.py:24` 和 `neoagent/core/compress.py:71`。这会让调用方难以推断“哪些能力需要 session 才正确”。建议在 loop 层统一保证始终有 session，内部 API 就不要再传 optional。

- `ToolExecutor` 捕获了过宽的 `except Exception`，而且只返回 `str(e)`。见 `neoagent/tools/executor.py:89`。这会压平 validation error、permission error、tool runtime error，后续 hooks/MCP 很难做精确处理。建议引入几个小型异常类型。

- `observe_subscriber.py` 的订阅是手工展开的适配器表。见 `neoagent/observe_subscriber.py:21-29`。这个模式本身是对的，但现在没有 `unsubscribe()`/`close()`，多次 `enable_logging()` 只关文件不解绑 handler，老 subscriber 还会留在 bus 里。当前因为旧 observer 被 close 了，影响有限，但这是典型泄漏点。建议让 `ObserverSubscriber` 保存 handler 引用并提供 `detach()`。

- `JsonFileStorage` 没有版本字段，序列化格式演进空间不足。见 `neoagent/session.py:127`。v3.2 再给 `SessionState` 增字段时，还能靠默认值兜；但一旦 block/event schema 变化，兼容策略会很被动。建议加 `schema_version`。

## 轻微（改了更好）

- `neoagent/session.py` 和 `neoagent/config.py` 都还保留了未使用的 `field` import。见 `neoagent/session.py:5`、`neoagent/config.py:2`。

- `ToolRegistry.all_tools()` 当前没有被使用。见 `neoagent/tools/registry.py:26`。如果不是为后续 MCP 预留，可以删；如果是预留，建议加注释说明用途。

- `QueryLoop` 里导入了未使用的 `ToolResult`、`ToolUseBlock`、`Response`。见 `neoagent/core/loop.py:18-19`。

## v3.2 就绪度评估

- Session 系统：部分就绪。把大部分跨轮态迁进了 `SessionState` 是对的，但还漏了 compressor failure 计数，而且 `fork()` 隔离不成立，`run(messages, session=...)` 还存在状态污染语义。要上 Multi-Agent，先把“session 真隔离”做实。

- EventBus：概念就绪，机制未封口。基础观察者模式已经成立，`emit-never-throws` 也工作正常；但事件对象不真不可变，未发出的事件类型又太多，说明事件体系还没稳定。要做 Hooks，必须先决定事件是“纯观察”还是“可干预”，不能继续混着来。

- ToolExecutor：方向正确，MCP 还差一层抽象。把 registry 执行逻辑剥离出来是正确重构，但现在 executor 仍强依赖本地 `BaseTool`/`Pydantic input_model`。v3.2 要接 MCP，建议再抽一层 `ToolBackend`/`ToolAdapter`。

- BashTool：不适合作为安全边界。restricted shell + env whitelist 比 v2 好，但仍只是 best-effort。v3.2 前至少要把文档和测试定位改准确，不要让调用方误以为它“安全”。

- 需要在 v3.2 前清理的架构债务：
  1. 把所有跨 session 状态完整收敛到 `SessionState`
  2. 修复 `Session.fork()` 深拷贝和 `session_id` 路径约束
  3. 明确 EventBus 是 observational 还是 interceptable
  4. 给 `ObserverSubscriber` 增加解绑
  5. 给 ToolExecutor 准备 provider-agnostic/backend-agnostic 适配层
  6. 把未发射的事件要么补齐要么删除

## 总结评价

- 整体评分：7.8/10

- 与上次 review（v2，6.5/10）相比，这次架构方向明显更成熟了。`Session`、`EventBus`、`ToolExecutor` 这三刀基本都砍在正确位置上，v3.2 的扩展面也比 v2 清楚得多。但这次的问题更偏“边界定义”和“语义闭环”：不是大面积设计错误，而是还有几处关键口子没封严。

- 最优先的 5 件事：
  1. 修复 `Session.fork()` 的浅拷贝问题。
  2. 给 `JsonFileStorage` 加 session id 路径约束。
  3. 把 compressor failure state 搬进 `SessionState`。
  4. 修正 Event 对象的伪不可变问题，至少切断 handler 对运行态的原地篡改。
  5. 明确 `BashTool` 的安全定位，并处理 timeout 的进程树清理。

- 做得好的地方：
  - `ToolRegistry`/`ToolExecutor` 的职责拆分是成立的，方向正确。
  - `QueryLoop` 同时兼容 Session API 和 legacy list API，迁移策略务实。
  - `Session` 持久化和 agent 侧 `new_session()/resume()/chat(session=)` 接口整体可用，迁移成本低。
  - `ObserverSubscriber` 作为适配器保住了旧 `Observer` 投资，这个重构很克制。
  - 测试面显著扩大，v3.1 关键新模块都至少有基础覆盖。
