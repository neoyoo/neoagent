# neoagent v3.2b Code Review R2

日期: 2026-04-12  
审查对象: neoagent v3.2b Multi-Agent 实现  
审查类型: 更新版复审  
权威参考: `docs/superpowers/specs/2026-04-12-neoagent-v3.2b-design.md`

## 复审结论

这版相对上一版有实质进步，已经修掉了几项明确问题：

- `pyyaml` 已加入 `pyproject.toml`
- `TaskTracker` 现在记录 `worker_name`
- `spawn_worker` / `delegate_task` 已把真实 `_run_worker()` 包装进 `asyncio.create_task()` 并登记到 `TaskTracker`
- `timeout` 已从 `failed` 修正为 `cancelled`
- 事件发射 helper 已收敛到共享实现
- task_id 已统一为完整 UUID

但当前版本仍然没有达到可以放心合并的程度，原因是还存在一个新的运行时阻断 bug，以及几个仍未闭环的语义问题。

最关键的新发现是：

- 真实 `Orchestrator` 只有 `self.config`
- `_create_worker_agent()` 却读取 `orchestrator._config`

这意味着真实 `spawn_worker` / `delegate_task` 在未打 patch 的情况下会直接抛 `AttributeError`。现有测试之所以没暴露，是因为大量路径把 `_create_worker_agent()` mock 掉了。

## 已修复项

### 1. 取消链路已部分接通

- `spawn_worker.py:96`
- `delegate_task.py:115`

### 2. 超时状态已修正

- `task.py:376`

现在 `TimeoutError` 会映射成 `TaskResult(status="cancelled")`，这符合 spec。

### 3. 任务观测性有所提升

- `task.py:121`
- `task.py:177`
- `list_tools.py:63`

`TaskTracker` 现在会记录 `worker_name`，`list_tasks` 的输出比上一版更有用。

### 4. 重复代码已收敛

- `neoagent/multi/tools/__init__.py:30`

事件发射 helper 不再在两个 tool 文件中重复拷贝，这个改动是正确的。

## 严重问题（必须修复）

### 1. 真实 Orchestrator 与 _create_worker_agent 协议不一致，运行时会直接炸

- **问题描述**
  `Orchestrator.__init__()` 保存的是 `self.config`，但 `_create_worker_agent()` 读取的是 `orchestrator._config`。真实运行 `spawn_worker` 或 `delegate_task` 时，worker factory 会访问不存在的属性。
- **文件和行号**
  - `neoagent/multi/orchestrator.py:42`
  - `neoagent/multi/worker.py:95`
- **风险**
  这是一个真实运行时阻断 bug。只要不 mock `_create_worker_agent()`，多 agent 主路径就会直接失败。
- **修复建议**
  统一配置字段命名。最小修法是让 `Orchestrator` 同时保存 `self._config = config`；更干净的修法是让 `_create_worker_agent()` 使用 `orchestrator.config`，不要依赖私有属性。

### 2. Task 级约束仍没有真正透传到 Worker 运行时

- **问题描述**
  当前 `Task.max_turns` 只是数据字段，`_run_worker()` 调 `agent.run(messages=messages)` 时没有把 task 级 `max_turns` 传进去；`max_tokens` 更是没有实现。
- **文件和行号**
  - `neoagent/multi/task.py:38`
  - `neoagent/multi/task.py:323`
  - `neoagent/agent.py:119`
- **风险**
  spec 第 7 节要求的多层防护没有真正落到运行时。当前 worker 实际受的是 agent config 的全局 `max_turns`，而不是 task envelope 的约束。
- **修复建议**
  扩展 `NeoAgent.run()` / `QueryLoop.run()` 支持 per-task `max_turns/max_tokens`，不要让 `Task` 里的限制成为无效字段。

### 3. work_summary 仍然无法拿到真实执行历史

- **问题描述**
  `_run_worker()` 在取消和超时分支里尝试读取 `agent.session.messages`，但 `NeoAgent` 并没有 `session` 属性。异常被吞掉后，会退回到初始输入消息列表，而 `_extract_work_summary()` 只看 assistant/tool_use 内容，因此大多数情况下只会得到空摘要或退化摘要。
- **文件和行号**
  - `neoagent/multi/task.py:360`
  - `neoagent/multi/task.py:379`
  - `neoagent/agent.py:119`
- **风险**
  虽然现在状态是 `cancelled` 了，但 spec 要求的“取消后保留工作摘要”仍未真正实现。Orchestrator 仍然拿不到可靠的部分进展信息。
- **修复建议**
  用显式 `Session` 对象运行 worker，并把这个 session 句柄传给 `_run_worker()`。取消/超时时直接从该 session 读取消息历史，不要猜测 `agent.session` 是否存在。

## 重要问题（建议修复）

### 4. delegate_task 仍不是并发安全工具，静态 worker 并行路径没完全落地

- **问题描述**
  `SpawnWorkerTool` 是 `is_concurrent_safe=True`，但 `DelegateTaskTool` 仍然不是。因此同一轮模型若产出多个 `delegate_task` 调用，`ToolExecutor` 会串行执行它们。
- **文件和行号**
  - `neoagent/multi/tools/delegate_task.py:42`
  - `neoagent/tools/base.py:13`
  - `neoagent/tools/executor.py:57`
- **风险**
  spec 中“静态 worker + 并行执行”的核心场景没有完整成立。
- **修复建议**
  在确认其内部状态无共享副作用后，将 `DelegateTaskTool` 标记为并发安全，或提供单独的 submit API。

### 5. 等待 Semaphore 的任务无法取消

- **问题描述**
  task 在 `track()` 之后、进入 `async with semaphore` 之前就已经出现在 tracker 中；但只有拿到 semaphore 之后才会 `set_asyncio_task()`。因此如果任务正卡在 semaphore 等待阶段，`cancel_task()` 会返回 `False`。
- **文件和行号**
  - `neoagent/multi/tools/spawn_worker.py:94`
  - `neoagent/multi/tools/spawn_worker.py:95`
  - `neoagent/multi/tools/delegate_task.py:113`
  - `neoagent/multi/tools/delegate_task.py:114`
- **风险**
  在高并发或限流场景下，队列中的任务不可取消，语义不完整。
- **修复建议**
  把“排队中的任务”也包装成顶层 `asyncio.Task` 并尽早注册，内部再去等待 semaphore。

### 6. 工具实例仍在多个 worker 之间共享

- **问题描述**
  `_create_worker_agent()` 直接复用 orchestrator `_tool_pool` 中的 tool 实例。
- **文件和行号**
  - `neoagent/multi/worker.py:114`
- **风险**
  只要工具有实例状态，就会出现 worker 之间的状态串扰或竞态。
- **修复建议**
  把 tool pool 升级成 tool factory / blueprint，worker 创建时实例化自己的本地工具对象。

## 次要问题（可选修复）

### 7. 类型注解与运行时值仍不一致

- **问题描述**
  `TaskResult.usage` 和 `TaskResult.work_summary` 的注解是非可选，但当前代码多处传 `None`。
- **文件和行号**
  - `neoagent/multi/task.py:73`
  - `neoagent/multi/task.py:347`
  - `neoagent/multi/task.py:367`
  - `neoagent/multi/task.py:386`
- **风险**
  类型系统会持续误导维护者和测试。
- **修复建议**
  改成显式可选类型。

### 8. Task 仍然只是浅不可变

- **问题描述**
  `Task` 是 frozen dataclass，但 `metadata` 仍然是可变 `dict`。
- **文件和行号**
  - `neoagent/multi/task.py:41`
- **风险**
  “frozen” 的语义不完整。
- **修复建议**
  用不可变映射或在构造时冻结元数据。

## 测试评估

### 当前状态

本地直接运行：

```bash
pytest -q tests/multi
```

仍然会因为当前 shell 环境未安装 `yaml` 而在收集阶段失败。

进一步尝试：

```bash
uv run pytest -q tests/multi
```

被网络依赖阻塞，无法从 PyPI 拉取 `pytest-asyncio`。

### 结论

这说明两件事：

1. 代码层面已经补了 `pyyaml` 声明，但当前本地环境没有同步到最新依赖，无法直接验证
2. 即使抛开环境问题，测试本身仍然没有覆盖最关键的真实运行路径

### 仍然存在的测试缺口

- `tests/multi/test_worker.py` 中的 orchestrator 替身使用的是 `orch._config`，恰好掩盖了真实 `Orchestrator` 只有 `config` 的 bug
- `tests/multi/test_integration.py` 仍然大量 patch `_create_worker_agent()`，导致真实 worker factory 主路径没有被测到
- 没有测试能证明 `work_summary` 在真实取消/超时后包含实际工具调用与 assistant 输出
- 没有测试验证 task 级 `max_turns` 是否真的生效

## 亮点

- 更新版明显在修正上一轮 review 的核心问题，说明改动方向是对的
- 取消链路已经从“只有接口”进展到“有真实 task 句柄”
- timeout 语义修正到 `cancelled` 是一次关键进步
- 共享 helper 收敛和 UUID 统一都提升了实现一致性

## 建议的修复顺序

1. 修复 `Orchestrator.config` / `_config` 不一致
2. 用显式 `Session` 跑 worker，真正拿到可用 `work_summary`
3. 把 task 级 `max_turns/max_tokens` 透传到运行时
4. 让 `delegate_task` 支持真实并行
5. 补一组不 mock `_create_worker_agent()` 的端到端测试

## 最终判断

这版比上一版确实更好，已经修掉了几项明确问题，但还不能判定为“Multi-Agent 主路径已稳定”。

当前最值得重视的点不是上一版那些已知问题，而是这次新确认的真实运行时断点：

- worker factory 读错 orchestrator 配置字段
- work_summary 仍然拿不到真实会话历史
- task 级限制仍未真正生效

只要这三个问题还在，v3.2b 就还不能算真正完成闭环。
