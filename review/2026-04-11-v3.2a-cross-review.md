## 严重（必须修复）

- `pre_tool_call` 的 `modify` 可以在权限检查之后改写参数，但不会重新走 `PermissionChecker`，这会直接绕过 `"ask"`/高风险工具的审批语义。位置：[neoagent/tools/executor.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/executor.py#L81) [neoagent/tools/executor.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/executor.py#L112)。当前流程是“先 `check()`，再 hook modify，再只做 `model_validate()`”。对 `bash`、文件写入、MCPTool 这类工具，hook 可以把已批准的安全输入改成未批准的危险输入。  
  为什么重要：这是明确的安全边界穿透，不是单纯的 API 不优雅。  
  建议修复：
  ```python
  if pre_result.action == "modify" and pre_result.modified_data:
      new_input = pre_result.modified_data.get("tool_input", call.input)
      call = ToolCall(id=call.id, name=call.name, input=new_input)
      validated_input = tool.input_model.model_validate(call.input)
      allowed = await self._permission.check(tool, validated_input)
      if not allowed:
          ...
  ```

- MCP 客户端没有校验 JSON-RPC `id`，也没有处理服务端通知/乱序响应，协议正确性是不成立的。位置：[neoagent/mcp/client.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/client.py#L52) [neoagent/mcp/client.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/client.py#L66) [neoagent/mcp/client.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/client.py#L85) [neoagent/mcp/client.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/client.py#L97) [neoagent/mcp/client.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/client.py#L119) [neoagent/mcp/client.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/client.py#L135)。现在是“发一个请求，就读下一条消息”，这在 MCP server 发 notification、progress、日志，或者未来做并发 call 时会直接串台。  
  为什么重要：这会导致错误结果绑定到错误请求，属于运行时 correctness 问题。  
  建议修复：抽一个 `_request()`，循环读消息，忽略 notification，把不匹配 `id` 的响应缓存到 pending map，直到拿到当前 request id 的响应。

- `StdioTransport` 把子进程 `stderr` 接到了 `PIPE`，但从未消费；只要 MCP server 持续往 `stderr` 打日志，就可能因 pipe 填满而卡死整个会话。位置：[neoagent/mcp/transport.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/transport.py#L67) [neoagent/mcp/transport.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/transport.py#L73)。  
  为什么重要：stdio 型 server 非常常见会写诊断日志，这会造成真实线上 hang。  
  建议修复：要么像 BashTool 一样并到 stdout，要么启动后台 task 持续 drain stderr 并按 debug/warning 记录，`close()` 时一并取消/回收。

## 重要（应该修复）

- deferred loading 的可见性状态是 `NeoAgent` 级全局状态，不是 session 级状态；一个会话的 `tool_search/promote` 会影响另一个会话。位置：[neoagent/agent.py](/Users/neo/Desktop/project/git/neoagent/neoagent/agent.py#L38) [neoagent/agent.py](/Users/neo/Desktop/project/git/neoagent/neoagent/agent.py#L62) [neoagent/core/loop.py](/Users/neo/Desktop/project/git/neoagent/neoagent/core/loop.py#L116) [neoagent/core/loop.py](/Users/neo/Desktop/project/git/neoagent/neoagent/core/loop.py#L128) [neoagent/tools/builtin/tool_search.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/builtin/tool_search.py#L79) [neoagent/tools/builtin/tool_search.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/builtin/tool_search.py#L81)。  
  为什么重要：这对 v3.2b Multi-Agent/多 session 是明显架构阻塞。  
  建议修复：把“哪些工具已 promote”迁到 `SessionState`，`DeferredToolRegistry` 只保留全局索引。

- `remove_mcp_server()` 只从 `ToolRegistry` 私有字典里删工具，没有清理 `DeferredToolRegistry`，会留下 ghost entry；之后 `tool_search` 仍能搜到已移除工具名，虽然执行时会跳过。位置：[neoagent/agent.py](/Users/neo/Desktop/project/git/neoagent/neoagent/agent.py#L284) [neoagent/agent.py](/Users/neo/Desktop/project/git/neoagent/neoagent/agent.py#L294) [neoagent/tools/builtin/tool_search.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/builtin/tool_search.py#L65) [neoagent/tools/builtin/tool_search.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/builtin/tool_search.py#L75)。  
  为什么重要：会制造错误发现结果，生命周期不闭环。  
  建议修复：给 `DeferredToolRegistry` 增加 `remove(tool_names)`，并在 remove server 时同步删除；如果最后一个 MCP server 被移除，也应考虑移除/禁用 `tool_search`。

- Hook 事件声明成 `frozen dataclass`，但字段里放的是可变 `dict/list`，冻结只是浅层的；handler 仍可原地修改事件内容，绕过 `HookResult.modify` 协议。位置：[neoagent/hooks.py](/Users/neo/Desktop/project/git/neoagent/neoagent/hooks.py#L42) [neoagent/hooks.py](/Users/neo/Desktop/project/git/neoagent/neoagent/hooks.py#L78)。尤其是 `tool_input: dict`、`messages: list[Message]`、`tools: list[dict]`。  
  为什么重要：这会让 hook 的语义不可预测，也让“只允许通过 HookResult 修改”的约束失效。  
  建议修复：把这些字段改成不可变类型：`MappingProxyType`/`tuple`，或者在构造事件前深拷贝并转只读结构。

- `tool_search` 默认 `permission="auto"`，且直接返回完整 schema；这意味着模型无需审批就能枚举 deferred MCP 工具的描述和参数结构。位置：[neoagent/tools/builtin/tool_search.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/builtin/tool_search.py#L25) [neoagent/tools/builtin/tool_search.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/builtin/tool_search.py#L45) [neoagent/tools/builtin/tool_search.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/builtin/tool_search.py#L65) [neoagent/tools/builtin/tool_search.py](/Users/neo/Desktop/project/git/neoagent/neoagent/tools/builtin/tool_search.py#L84)。  
  为什么重要：如果某些 MCP tool description/schema 含内部系统细节，这就是设计级信息泄漏。  
  建议修复：增加 `discoverable: bool` 或 server policy，或者让 `tool_search` 只返回 name+summary，真正 schema 在 promote 后才暴露。

- `MCPTool` 的 JSON Schema 到 Pydantic 转换过于简化，复杂 schema 会降级成宽松的 `list/dict/Any`，实际校验能力不足。位置：[neoagent/mcp/tool.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/tool.py#L24) [neoagent/mcp/tool.py](/Users/neo/Desktop/project/git/neoagent/neoagent/mcp/tool.py#L44)。  
  为什么重要：这会让 LLM 看到的 schema 和执行层的真实约束不一致，后续接 MCP 工具越多越痛。  
  建议修复：至少支持 `items`、nested object、enum、default；更稳妥的是保留原始 JSON Schema，并用独立 validator 做运行时校验。

## v3.2b 就绪度评估

- HookManager/EventBus：方向对了，但还没完全分层干净。EventBus 适合观察型、never-throws；HookManager 适合可拦截型。现在最大的缺口不是模式，而是“hook 是否可信”的安全边界没有落实。v3.2b 如果要接第三方 hook/plugin，必须先补“modify 后重鉴权”和不可变 event payload。

- MCP：执行通路已经打通，但 transport/client 还停留在“单请求串行 happy path”实现。要进入 Multi-Agent 或多个 MCP server 并发调用阶段，必须先补 response correlation、notification handling、stderr draining、断连恢复策略。

- Deferred loading：概念成立，但状态域错了。现在是 agent-global；v3.2b 做子 agent/session fork 时会互相污染。应拆成“全局工具索引 + session 级可见性集”。

- Tool backend 抽象：`MCPTool` 作为 `BaseTool` 适配器是可行的，但还缺一个更稳定的 backend contract。v3.2b 若计划支持更多远端工具源，建议抽 `ToolBackend`/`RemoteToolHandle`，把 schema 获取、权限默认、执行、健康检查分开。

- 生命周期：`add_mcp_server()/remove_mcp_server()/close()` 基本可用，但 server removal 还没有做到状态闭环。v3.2b 前要把 registry、deferred index、tool_search、client cleanup 放进一个统一 lifecycle manager。

## 总结评价

- 整体评分：`7.8/10`

- 最优先修复的 5 件事：
  1. 修掉 `pre_tool_call modify` 后不重跑权限检查的问题。
  2. 给 MCPClient 加 request/response `id` 关联和 notification 处理。
  3. 处理 StdioTransport 的 `stderr` drain，避免子进程死锁。
  4. 把 deferred promote 状态从 agent-global 挪到 session state。
  5. 完成 `remove_mcp_server()` 的状态闭环，不再留下 deferred ghost tool。

- 做得好的地方：
  - HookManager 和 EventBus 的职责方向是对的，pre/post 拦截点放置也基本合理。
  - `MCPTool -> BaseTool` 的适配很轻，能快速复用现有 ToolExecutor/PermissionChecker。
  - deferred loading 的用户体验思路是清晰的，`tool_search -> promote -> next turn visible` 这条链路工作正常。
  - 测试数量不少，而且 happy path 基本都打通了，说明这次重构不是“只改架构不保行为”。
