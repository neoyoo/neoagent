# neoagent v3.2b 设计规格：Multi-Agent

日期: 2026-04-12
版本: v3.2b
前置: v3.2a（Hooks + MCP）已合并 main，577 tests

## 目标

在 v3.2a 的 Hooks + MCP 基础上增加 Multi-Agent 能力，实现 Orchestrator + Workers 模式。Orchestrator 作为决策核心，将子任务委派给 Worker（每个 Worker 是独立的 NeoAgent 实例），支持静态预注册和 LLM 动态 spawn 两种模式。

## 范围

### 包含
- Orchestrator 类：决策核心，组合 NeoAgent 作为自身大脑
- WorkerCard 数据模型：Worker 自描述（能力、工具、模型）
- WorkerPool：静态 Worker 注册与能力匹配
- TaskTracker：任务生命周期管理（派发、超时、取消）
- 五个内建工具：spawn_worker / delegate_task / list_workers / cancel_task / list_tasks
- 并行执行：asyncio.gather 驱动的并发 Worker
- 深度控制：max_depth 硬性阻断无限递归
- 事件冒泡：Worker 内部事件包装后冒泡到 Orchestrator
- WorkerCard .md 文件格式与加载

### 不包含
- Channel/Interface 抽象（v3.2c）
- A2A（Agent-to-Agent Protocol，远期演进方向）
- Teams 多 Agent 共享上下文（远期）
- Worker .md 文件热加载（需要重启）
- 分布式调度（本地单进程）
- Pipeline 串行模式（手动串联可模拟）
- Peer 协作（Worker 间直接通信）
- 自动重试策略（由 LLM 决定）

## 设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 架构模式 | Orchestrator + Workers | 清晰的职责分离，符合主流 Multi-Agent 实践 |
| Worker 本质 | 独立 NeoAgent 实例（协议，不是类） | 复用完整基础设施；本地/远程只换传输层 |
| Worker 定义格式 | .md frontmatter 统一格式 | 人类可读，程序可解析，与知识库风格一致 |
| Worker 来源 | 三种（文件/代码/LLM动态） | 满足静态团队角色和动态临时任务两类场景 |
| 并发模型 | asyncio.gather | 天然 async，与现有 QueryLoop 一致 |
| 深度控制 | max_depth 硬性阻断 | 防止无限递归，不可绕过 |
| 取消机制 | asyncio.Task.cancel() + 优雅退出 | 等当前工具完成再退出，不丢中间结果 |
| work_summary | 确定性程序化提取 | 避免额外 LLM 调用，纯代码从消息历史提取 |
| 事件冒泡 | Python 回调层，不进 LLM 上下文 | Orchestrator LLM 只看 TaskResult，避免噪音 |
| 权限控制 | 显式授权 + 最小权限 | spawn 时指定工具集，不指定就没有 |

## 一、核心数据模型

### 1.1 Task Envelope（Orchestrator → Worker 通信）

```python
@dataclass(frozen=True)
class Task:
    task_id: str
    instruction: str          # 自然语言指令
    context: tuple[Message, ...]    # 可选上下文片段
    constraints: dict         # max_turns(默认20), max_tokens, timeout(默认1800s)
    metadata: dict            # 用户自定义透传
    max_output_tokens: int = 2000  # 限制 Worker 输出长度
```

### 1.2 TaskResult（Worker → Orchestrator 返回）

```python
@dataclass(frozen=True)
class TaskResult:
    task_id: str
    status: Literal["completed", "failed", "cancelled"]
    output: str
    error: str | None
    usage: TokenUsage | None
    work_summary: str | None    # 被取消时的工作摘要（程序化提取）
    turns_completed: int        # 实际完成轮次
```

### 1.3 WorkerCard（Worker 自描述）

```python
@dataclass(frozen=True)
class WorkerCard:
    name: str                 # 唯一标识
    description: str          # 能力描述，供 LLM 匹配
    instruction: str          # system prompt（md body 内容）
    tags: tuple[str, ...]     # 能力标签
    model: str | None         # 默认模型（None 则继承 Orchestrator 配置）
    tools: tuple[str, ...]    # 可用工具名列表（显式授权）
```

### 1.4 WorkerCard 三种来源

| 来源 | 持久化 | 注册方式 | 场景 |
|------|--------|----------|------|
| .md 文件 | 磁盘 | `orch.load_workers("workers/")` | 团队共享的固定角色 |
| Python 代码 | 代码库 | `orch.register_worker(WorkerCard(...))` | 程序化定义 |
| LLM 动态生成 | 仅内存 | `spawn_worker` tool 输出 md → 解析为 WorkerCard | 临时任务 |

### 1.5 WorkerCard .md 文件格式

```markdown
---
name: reviewer
model: sonnet
tags: [review, security]
tools: [read, grep, glob]
---
你是一个严格的代码审查员。重点关注安全漏洞和性能问题。

## 审查标准
- OWASP Top 10
- 性能热路径
- ...
```

- frontmatter 字段：name（必填）、model（可选）、tags（可选）、tools（可选）
- md body 整体作为 instruction（system prompt）
- 解析失败时报错，不静默跳过

## 二、Orchestrator 架构

### 2.1 架构概述

Orchestrator 是独立类，不继承、不侵入现有 `NeoAgent`/`agent.py`。它组合一个 NeoAgent 实例作为自身的决策引擎（大脑），同时管理 WorkerPool 和 TaskTracker 两个内部组件。

```
用户
  │  result = await orch.run("审查这三个文件的安全问题")
  ▼
Orchestrator
  ├─ NeoAgent（内嵌，跑 QueryLoop）
  │   → LLM 决策：拆任务 → 调用内建工具
  │   → delegate_task("reviewer", "审查 auth.py")
  │   → spawn_worker(md_def, "审查 utils.py")
  │
  ├─ WorkerPool
  │   → 管理静态 WorkerCard 注册
  │   → 能力匹配查询（供 list_workers 使用）
  │
  └─ TaskTracker
      → 追踪所有进行中/已完成 Task
      → 汇总结果
      → 管理超时和取消
```

### 2.2 三个内部组件

#### NeoAgent（内嵌）
- Orchestrator 自己的 QueryLoop 决策引擎
- 注册五个内建工具（见第三节）
- 在 depth=0 时，注册全部五个内建工具（包括 spawn_worker）

#### WorkerPool
- 管理静态 WorkerCard 的注册和查找
- `register(card: WorkerCard)` → 按 name 索引
- `find(name: str) -> WorkerCard | None`
- `list_all() -> list[WorkerCard]`
- name 冲突时覆盖并警告

#### TaskTracker
- `create_task(task: Task) -> str`（返回 task_id）
- `get_result(task_id: str) -> TaskResult | None`
- `list_active() -> list[str]`（进行中的 task_id）
- `list_all() -> list[dict]`（全部，含状态摘要）
- `cancel(task_id: str) -> bool`
- 超时到期后自动取消对应 asyncio.Task

### 2.3 用户 API

```python
# 创建 Orchestrator
orch = Orchestrator(
    config=NeoAgentConfig(model="opus"),
    max_depth=2,              # 最大递归深度，默认 2
    max_concurrent_workers=5, # 最大并发 Worker 数，默认 5
)

# 注册静态 Worker（两种方式）
orch.register_worker(card)          # 代码方式
orch.load_workers("workers/")       # 加载目录下所有 .md 文件

# 注册工具（Worker 可被授权使用的工具池）
orch.register_tool(read_tool)
orch.register_tool(grep_tool)

# 执行 — 用户只管发消息
result = await orch.run("审查这三个文件的安全问题")
```

## 三、内建工具

五个内建工具暴露给 Orchestrator 的 NeoAgent（LLM 可调用）。Worker 本身不注册这些工具，除非 Worker 的 depth < max_depth（此时 spawn_worker 可用）。

### 3.1 工具一览

| 工具 | 作用 | 参数 |
|------|------|------|
| spawn_worker | 动态创建临时 Worker | md_definition: str, instruction: str |
| delegate_task | 路由任务到已注册的静态 Worker | worker_name: str, instruction: str, context?: list |
| list_workers | 查看可用静态 Worker 列表及能力描述 | （无） |
| cancel_task | 取消指定运行中的任务 | task_id: str, reason?: str |
| list_tasks | 查看所有任务状态 | （无） |

### 3.2 spawn_worker

```python
class SpawnWorkerTool(BaseTool):
    """动态创建临时 Worker 并立即派发任务。
    md_definition 是 WorkerCard .md 格式字符串（frontmatter + body）。
    解析为 WorkerCard → 创建 NeoAgent → 派发 instruction。
    """
    name = "spawn_worker"
    permission = "auto"  # Orchestrator 信任的内部操作

    async def execute(self, input: SpawnWorkerInput) -> ToolResult:
        # 1. 解析 md_definition → WorkerCard（不注册到 WorkerPool，仅内存）
        # 2. 创建 Worker NeoAgent（depth=self.depth+1）
        # 3. 创建 Task，注册到 TaskTracker
        # 4. 启动 asyncio.Task 执行
        # 5. 等待结果（在并行场景由调用方 gather）
        # 6. 返回 TaskResult 摘要
```

### 3.3 delegate_task

```python
class DelegateTaskTool(BaseTool):
    """路由任务到已注册的静态 Worker。
    从 WorkerPool 查找 worker_name → 创建 Worker NeoAgent → 派发任务。
    """
    name = "delegate_task"
    permission = "auto"

    async def execute(self, input: DelegateTaskInput) -> ToolResult:
        # 1. WorkerPool.find(worker_name)，找不到 → 返回错误提示
        # 2. 创建 Worker NeoAgent（复用 WorkerCard 定义）
        # 3. 创建 Task，注册到 TaskTracker
        # 4. 执行并等待
        # 5. 返回 TaskResult 摘要
```

### 3.4 list_workers

## 四、Worker 实例化

### 4.1 Worker 是 NeoAgent，不是子类

```python
def _create_worker_agent(
    card: WorkerCard,
    orchestrator: "Orchestrator",
    depth: int,
) -> NeoAgent:
    """从 WorkerCard 创建独立的 NeoAgent 实例。"""
    config = NeoAgentConfig(
        model=card.model or orchestrator.config.model,
        system_prompt=card.instruction,
    )
    agent = NeoAgent(config)

    # 只注册 WorkerCard 授权的工具
    for tool_name in card.tools:
        tool = orchestrator._tool_pool.get(tool_name)
        if tool:
            agent.register_tool(tool)

    # 如果 depth < max_depth，注册 spawn_worker（允许再往下派）
    if depth < orchestrator.max_depth:
        agent.register_tool(_make_spawn_tool(orchestrator, depth))

    # 事件冒泡：Worker 内部事件 → Orchestrator EventBus
    _setup_event_bubble(agent, orchestrator, card.name, depth)

    return agent
```

### 4.2 Worker 执行流程

```python
async def _run_worker(
    agent: NeoAgent,
    task: Task,
    tracker: TaskTracker,
) -> TaskResult:
    """执行 Worker 任务，处理超时和取消。"""
    try:
        async with asyncio.timeout(task.constraints.get("timeout", 1800)):
            response = await agent.run(
                task.instruction,
                context=task.context,
                max_turns=task.constraints.get("max_turns", 20),
            )
        return TaskResult(
            task_id=task.task_id,
            status="completed",
            output=response.content,
            error=None,
            usage=response.usage,
            work_summary=None,
            turns_completed=response.turns,
        )
    except asyncio.CancelledError:
        summary = _extract_work_summary(agent)
        return TaskResult(
            task_id=task.task_id,
            status="cancelled",
            output="",
            error=None,
            usage=None,
            work_summary=summary,
            turns_completed=agent.turns_completed,
        )
    except Exception as e:
        return TaskResult(
            task_id=task.task_id,
            status="failed",
            output="",
            error=str(e),
            usage=None,
            work_summary=None,
            turns_completed=agent.turns_completed,
        )
```

## 五、并行执行

### 5.1 asyncio.gather 驱动

Orchestrator 的 LLM 可以通过多次调用 spawn_worker / delegate_task 来并行派发任务。内建工具默认异步等待单个任务，但 Orchestrator 可以批量启动后用 list_tasks 轮询，或一次性返回多个 task_id 供聚合。

更常见的模式是 Orchestrator LLM 依次调用多个 delegate_task，框架层面用 asyncio.gather 并发执行：

```python
# Orchestrator 内部的并行调度逻辑
async def _run_parallel(tasks: list[Task]) -> list[TaskResult]:
    semaphore = asyncio.Semaphore(self.max_concurrent_workers)

    async def _bounded(task):
        async with semaphore:
            return await _run_worker(...)

    return await asyncio.gather(
        *[_bounded(t) for t in tasks],
        return_exceptions=True,  # 单个失败包装为 TaskResult，不崩溃全局
    )
```

### 5.2 容错

- 单个 Worker 抛异常 → 包装为 `TaskResult(status="failed")`，不传播
- 并行任务中一个失败，其他继续运行
- `max_concurrent_workers` 通过 Semaphore 硬性限制并发上限

## 六、深度控制

### 6.1 防无限递归

```
depth=0  Orchestrator（有 spawn_worker）
  └─ depth=1  Worker（max_depth=2 时，仍有 spawn_worker）
      └─ depth=2  Sub-worker（depth >= max_depth，无 spawn_worker）
```

- Worker 在 `depth >= max_depth` 时，`_create_worker_agent` 不注册 `spawn_worker` 工具
- Sub-worker 的 LLM 无法看到 spawn_worker，物理上无法再往下派
- 这是硬性阻断，不依赖提示词约束

### 6.2 默认值

| 参数 | 默认值 | 说明 |
|------|--------|------|
| max_depth | 2 | Orchestrator→Worker→Sub-worker，三层 |
| max_concurrent_workers | 5 | 同时运行的 Worker 上限 |

## 七、多层防护与超时

### 7.1 防护层次

| 防护层 | 类型 | 控制参数 | 默认值 |
|--------|------|----------|--------|
| max_turns | 软约束 | Task.constraints["max_turns"] | 20 轮 |
| max_tokens | 软约束 | Task.constraints["max_tokens"] | 无限制 |
| timeout | 硬约束（兜底） | Task.constraints["timeout"] | 1800s（30分钟） |
| max_output_tokens | 输出截断 | Task.max_output_tokens | 2000 tokens |

- turns 和 tokens 是主要约束，由 QueryLoop 自然终止
- timeout 是墙钟兜底，通过 `asyncio.timeout()` 实现，防止 Worker 卡死
- max_output_tokens 限制 Worker 输出长度，防止结果过大撑爆 Orchestrator 上下文

### 7.2 token 预算透传

```python
# Task.constraints 透传给 Worker 的 QueryLoop
agent.run(
    task.instruction,
    max_turns=task.constraints.get("max_turns", 20),
    max_tokens=task.constraints.get("max_tokens"),  # None = 无限制
)
```

## 八、取消机制

### 8.1 三个取消场景

| 场景 | 触发方 | 实现 |
|------|--------|------|
| 用户取消 | 用户（Ctrl+C / API） | Orchestrator.cancel() → 级联取消所有运行中 Worker |
| LLM 主动取消 | Orchestrator LLM 调用 cancel_task | TaskTracker.cancel(task_id) → asyncio.Task.cancel() |
| Orchestrator 销毁 | __aexit__ / close() | 自动取消所有运行中 Worker（cleanup） |

### 8.2 优雅退出

`asyncio.Task.cancel()` 会向 Worker 的 QueryLoop 注入 `CancelledError`。QueryLoop 捕获后：
1. 等待当前工具调用完成（不强杀）
2. 清理 session 状态
3. 向上传播 `CancelledError`
4. `_run_worker` 捕获，生成 `TaskResult(status="cancelled")`

### 8.3 work_summary 生成（确定性，不调 LLM）

```python
def _extract_work_summary(agent: NeoAgent) -> str:
    """从 Worker 的消息历史程序化提取工作摘要。不调用 LLM。"""
    messages = agent.session.messages

    # 提取已调用的工具列表
    tool_calls = [
        f"{m.tool_name}({_truncate(m.tool_input, 50)})"
        for m in messages if m.role == "tool_call"
    ]

    # 最后一条 assistant 消息（如有）
    last_assistant = next(
        (m.content for m in reversed(messages) if m.role == "assistant"),
        None,
    )

    parts = []
    if tool_calls:
        parts.append(f"已执行工具: {', '.join(tool_calls[-5:])}")  # 最近5个
    if last_assistant:
        parts.append(f"最后输出: {_truncate(last_assistant, 200)}")

    return "\n".join(parts) if parts else "（无有效工作摘要）"
```

## 九、事件与可观测性

### 9.1 新增事件类型

```python
@dataclass(frozen=True)
class WorkerEvent:
    """Worker 内部事件的冒泡包装。"""
    worker_name: str
    task_id: str
    depth: int
    inner: Event  # 原始事件（ToolCallEvent、ProviderResponseEvent 等）

@dataclass(frozen=True)
class TaskDispatchEvent:
    """Orchestrator 派发任务时触发。"""
    task_id: str
    worker_name: str
    instruction: str
    depth: int

@dataclass(frozen=True)
class TaskCompleteEvent:
    """Worker 完成任务时触发。"""
    task_id: str
    worker_name: str
    status: Literal["completed", "failed", "cancelled"]
    turns_completed: int
    usage: TokenUsage | None
```

### 9.2 冒泡机制

```python
def _setup_event_bubble(
    worker_agent: NeoAgent,
    orchestrator: "Orchestrator",
    worker_name: str,
    depth: int,
) -> None:
    """订阅 Worker 的 EventBus，将事件包装后重新发布到 Orchestrator EventBus。"""
    def bubble_handler(event):
        wrapped = WorkerEvent(
            worker_name=worker_name,
            task_id=current_task_id,
            depth=depth,
            inner=event,
        )
        orchestrator._event_bus.emit(wrapped)  # 同步回调，不阻塞

    worker_agent.event_bus.subscribe_all(bubble_handler)
```

- 冒泡是纯 Python 回调，不进入 LLM 上下文
- Orchestrator 的 LLM 只看到 TaskResult（最终结果）
- `bubble_events` 可选参数：控制冒泡哪些事件类型（None = 全部）

### 9.3 Observer 日志格式

Observer 自动接收 Worker 事件，日志输出格式：

```
[worker:reviewer][task:abc123] ToolCall: grep(pattern="SQL injection")
[worker:reviewer][task:abc123] ToolResult: grep → 3 matches found
[worker:spawned-1][task:def456][depth:1] ToolCall: read(path="auth.py")
```

## 十、错误处理

### 10.1 错误隔离原则

| 错误类型 | 处理方式 |
|----------|----------|
| Worker 执行失败（异常） | 包装为 `TaskResult(status="failed", error=str(e))`，不崩 Orchestrator |
| Worker 超时 | asyncio.timeout 触发 CancelledError → status="cancelled" |
| spawn_worker md 解析失败 | 返回工具错误结果，Orchestrator LLM 可选择重试或换方案 |
| delegate_task worker 不存在 | 返回错误提示（建议 list_workers 确认可用列表） |
| 并行任务部分失败 | 失败的包装为 failed，其他继续；Orchestrator LLM 收到全部结果后自行决策 |

### 10.2 不自动重试

- 不实现自动重试策略
- 由 Orchestrator LLM 根据 TaskResult 判断是否值得重试
- 这样可以让 LLM 结合上下文智能决策（调整指令重试 vs 降级处理 vs 报告失败）

### 10.3 Hook 独立性

- Orchestrator 和每个 Worker 各自有独立的 HookManager
- Orchestrator 的 hook 不会影响 Worker 内部执行，反之亦然
- 用户可以对 Worker 的 agent 对象单独注册 hook（通过 `spawn_worker` 回调接口，未来扩展）

## 十一、权限控制

### 11.1 显式授权原则

- Worker 只能使用 WorkerCard.tools 中列出的工具
- 未在列表中的工具，即使 Orchestrator 注册了，Worker 也无法访问
- spawn_worker 时 md_definition 中的 tools 字段同样适用

### 11.2 工具池

```python
# Orchestrator 维护全局工具池
orch.register_tool(read_tool)   # 加入工具池（Worker 可申请授权）

# WorkerCard 声明使用哪些工具
card = WorkerCard(name="reviewer", tools=["read", "grep"], ...)

# 创建 Worker 时按 WorkerCard.tools 过滤
agent = _create_worker_agent(card, orch, depth)
# → agent 只有 read + grep，无法调用 bash 等其他工具
```

### 11.3 复用 PermissionChecker

- Worker 内部的 PermissionChecker 正常工作

## 十四、远期演进

### 14.1 Worker 是协议，不是类

Worker 接口的本质：接受 Task，返回 TaskResult。当前实现是本地 NeoAgent。未来可以替换为：

```python
class WorkerProtocol(Protocol):
    async def assign(self, task: Task) -> str:  # task_id
        ...

    async def get_result(self, task_id: str) -> TaskResult | None:
        ...
```

### 14.2 A2A（Agent-to-Agent Protocol）

未来加 `A2AWorker` 实现 WorkerProtocol，通过 HTTP/JSON-RPC 调用远程 agent。Orchestrator 的调度逻辑不变，只换传输层。

### 14.3 Teams 模式

多 agent 共享项目上下文 + 协调策略（v3.3+ 规划）。

## 十五、不做的事（显式排除 YAGNI）

- 不做 Pipeline 串行模式（手动串联调用可模拟）
- 不做 Peer 协作（Worker 间直接通信，都通过 Orchestrator 中转）
- 不做分布式调度（本地单进程，A2A 是远期）
- 不做 Worker .md 文件热加载（重启重新加载）
- 不做自动重试策略（LLM 决定）
- 不做 Worker 运行时 hook 注册 API（v3.2b 范围外）
- 不做 Worker 结果流式输出（TaskResult 是完整结果）
- 不做跨 Worker 的共享内存/会话
