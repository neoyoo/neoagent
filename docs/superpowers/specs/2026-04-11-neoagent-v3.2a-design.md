# neoagent v3.2a 设计规格：Hooks + MCP

日期: 2026-04-11
版本: v3.2a
前置: v3.1（Session + EventBus + ToolExecutor + BashTool）已合并 main，386 tests

## 目标

在 v3.1 的 EventBus 基础上增加可拦截式 Hook 系统，并集成 MCP 客户端 + 延迟工具加载，为 v3.2b（Multi-Agent）打下基础设施。

## 范围

### 包含
- Hooks：可拦截式事件系统（EventBus 演进）
- MCP：stdio 客户端 + 延迟加载（DeerFlow 模式）

### 不包含
- Multi-Agent（v3.2b）
- Channel/Interface 抽象（v3.2c）
- MCP Server 端（双向 MCP）
- SSE/HTTP 传输（预留接口，不实现）
- Shell hook / 配置文件注册（纯代码注册）

## 设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| Hooks 模式 | 可拦截式（方案 B） | 自然演进 EventBus + PermissionChecker；拦截对自用价值最大 |
| MCP 范围 | 客户端 + 延迟加载（方案 B） | DeerFlow 验证模式可行；Claude Code 自身也用延迟加载 |
| Hook 注册方式 | 函数式 + 装饰器（A+C） | Python SDK 用户即 Python 开发者；shell hook 暂无场景 |
| 拦截事件集 | 4 个核心事件 | 先做工具+LLM 核心链路，观察型事件保持 EventBus |
| MCP 传输 | 只做 stdio | 覆盖 90% MCP Server；预留 Transport 接口 |
| MCP 依赖 | 自实现 stdio，不引入 langchain | 保持轻量；langchain-mcp-adapters 太重 |

## 一、Hooks 系统

### 1.1 架构概述

在现有 EventBus（观察型）之上增加 HookManager（拦截型）。两者职责分离：

- **EventBus**：纯观察，handler 不能影响执行流程（已有，不变）
- **HookManager**：可拦截，handler 可以 allow/deny/modify 执行（新增）

```
QueryLoop 执行流程:
  ┌─ HookManager.run_pre("pre_provider_call", event)
  │   → 可修改 messages / system prompt
  │   → 可 deny 阻止 LLM 调用
  ├─ Provider.create()
  ├─ HookManager.run_post("post_provider_call", event)
  │   → 可修改响应
  ├─ EventBus.emit(ProviderResponseEvent)  ← 观察型，不变
  │
  ├─ HookManager.run_pre("pre_tool_call", event)
  │   → 可修改 input / deny 工具调用
  ├─ ToolExecutor.execute()
  ├─ HookManager.run_post("post_tool_call", event)
  │   → 可修改 result
  └─ EventBus.emit(ToolResultEvent)  ← 观察型，不变
```

### 1.2 核心类型

#### HookResult

```python
@dataclass(frozen=True)
class HookResult:
    action: Literal["allow", "deny", "modify"]
    reason: str | None = None
    modified_data: dict | None = None

    @classmethod
    def allow(cls) -> "HookResult":
        return cls(action="allow")

    @classmethod
    def deny(cls, reason: str = "") -> "HookResult":
        return cls(action="deny", reason=reason)

    @classmethod
    def modify(cls, data: dict, reason: str | None = None) -> "HookResult":
        return cls(action="modify", modified_data=data, reason=reason)
```

#### Hook 事件类型

```python
@dataclass(frozen=True)
class PreToolCallEvent:
    tool_name: str
    tool_input: dict
    call_id: str

@dataclass(frozen=True)
class PostToolCallEvent:
    tool_name: str
    tool_input: dict
    call_id: str
    result: str
    is_error: bool

@dataclass(frozen=True)
class PreProviderCallEvent:
    system: str
    messages: list[Message]
    tools: list[dict]

@dataclass(frozen=True)
class PostProviderCallEvent:
    response: Response
    input_tokens: int
    output_tokens: int
```

#### HookManager

```python
HookType = Literal["pre_tool_call", "post_tool_call", "pre_provider_call", "post_provider_call"]
HookHandler = Callable[..., Awaitable[HookResult]]

class HookManager:
    def register(self, hook_type: HookType, handler: HookHandler, priority: int = 0) -> None:
        """注册 hook handler。priority 越小越先执行。"""

    def unregister(self, hook_type: HookType, handler: HookHandler) -> None:
        """注销 hook handler。"""

    async def run_pre(self, hook_type: HookType, event: Any) -> HookResult:
        """串行执行 pre hooks。
        - 第一个 deny 立即短路返回
        - modify 会累积应用到 event
        - handler 抛异常 → 记录日志，跳过该 handler，继续
        - 所有 handler 都 allow → 返回 allow
        """

    async def run_post(self, hook_type: HookType, event: Any) -> HookResult:
        """串行执行 post hooks。
        - deny 在 post 阶段无意义（已执行完），忽略
        - modify 可累积修改 result
        - handler 抛异常 → 记录日志，跳过
        """
```

### 1.3 注册 API

```python
# 函数式注册
agent.hook("pre_tool_call", my_guard_handler, priority=0)

# 装饰器注册
@agent.on("pre_tool_call", priority=0)
async def my_guard(event: PreToolCallEvent) -> HookResult:
    if event.tool_name == "bash" and "rm -rf" in str(event.tool_input):
        return HookResult.deny("dangerous command blocked")
    return HookResult.allow()

# 注销
agent.unhook("pre_tool_call", my_guard_handler)
```

### 1.4 执行语义

| 规则 | 说明 |
|------|------|
| 执行顺序 | 按 priority 升序（0 最先），同 priority 按注册顺序 |
| pre hook 短路 | 任一 handler 返回 deny → 立即停止，不执行后续 handler 和目标操作 |
| pre hook modify | modify 结果传递给下一个 handler 作为输入（链式修改） |
| post hook deny | 忽略（操作已完成） |
| post hook modify | 可修改返回值，链式传递 |
| handler 异常 | 捕获 + 日志警告，跳过该 handler，不中断流程 |
| 无 handler | 等价于 allow |

### 1.5 与 EventBus 的关系

- HookManager 和 EventBus 是并列的，不是替代
- 同一个操作（如工具调用）先走 HookManager（拦截），再走 EventBus（通知）
- 如果 pre hook deny 了操作，EventBus 不会收到对应的完成事件
- 未来如果需要更多拦截点，只需在 HookManager 中增加 hook type，EventBus 不变

### 1.6 与 PermissionChecker 的关系

PermissionChecker 是工具级别的 auto/ask/deny 权限控制，在 ToolExecutor 内部执行。pre_tool_call hook 在 PermissionChecker **之后**执行（已通过权限检查的调用才会触发 hook）。这避免了 hook 和 permission 的语义冲突。

### 1.7 文件规划

| 文件 | 职责 |
|------|------|
| `neoagent/hooks.py`（新建） | HookManager、HookResult、4 个 Hook 事件类型 |
| `neoagent/agent.py`（修改） | 暴露 agent.hook() / agent.on() / agent.unhook() |
| `neoagent/core/loop.py`（修改） | 在 provider 调用和工具调用前后插入 hook 执行点 |
| `neoagent/tools/executor.py`（修改） | pre/post tool_call hook 集成（在 permission check 之后） |

## 二、MCP 系统

### 2.1 架构概述

参考 DeerFlow 的延迟加载模式。核心原则：**执行层全量注册，LLM 可见层按需暴露。**

```
agent.add_mcp_server("github", command=["npx", "@mcp/server-github"])
  │
  ▼
MCPClient（stdio 子进程）
  → initialize 握手
  → tools/list 获取工具列表
  │
  ▼
每个 MCP 工具 → MCPTool（实现 BaseTool 接口）
  → 注册到 ToolRegistry（执行层可调用）
  → 注册到 DeferredToolRegistry（索引：name + description）
  │
  ▼
每轮 LLM 调用前:
  → PromptBuilder 注入 <deferred-tools> 名单到 system prompt
  → 过滤：deferred 工具的 schema 不传给 LLM
  → tool_search 的 schema 传给 LLM
  │
  ▼
模型调用 tool_search("github__create_issue")
  → DeferredToolRegistry.search() 匹配
  → 返回完整 schema（JSON）
  → promote() 将该工具从 deferred 移出
  │
  ▼
下一轮 LLM 调用:
  → 该工具 schema 不再被过滤，LLM 可见
  → 模型正式调用 github__create_issue(...)
  → MCPTool.execute() → MCPClient 发 tools/call → 返回结果
```

### 2.2 核心类型

#### Transport（传输层抽象）

```python
class MCPTransport(ABC):
    """MCP 传输层抽象，预留 SSE/HTTP 扩展。"""
    async def connect(self) -> None: ...
    async def send(self, message: dict) -> None: ...
    async def receive(self) -> dict: ...
    async def close(self) -> None: ...

class StdioTransport(MCPTransport):
    """stdio 传输：通过子进程的 stdin/stdout 通信。"""
    def __init__(self, command: list[str], env: dict[str, str] | None = None): ...
    # 子进程管理、JSON-RPC 读写、环境变量白名单
```

#### MCPClient

```python
class MCPClient:
    """管理与单个 MCP Server 的连接生命周期。"""
    def __init__(self, name: str, transport: MCPTransport): ...

    async def connect(self) -> None:
        """握手：initialize → initialized notification"""

    async def list_tools(self) -> list[MCPToolInfo]:
        """获取工具列表：tools/list"""

    async def call_tool(self, tool_name: str, arguments: dict) -> str:
        """调用工具：tools/call → 返回结果文本"""

    async def close(self) -> None:
        """关闭连接和子进程"""

@dataclass
class MCPToolInfo:
    name: str
    description: str
    input_schema: dict  # JSON Schema
```

#### MCPTool（BaseTool 适配器）

```python
class MCPTool(BaseTool):
    """将 MCP 工具包装为 BaseTool，走统一的 ToolExecutor 管道。"""
    name: str            # "{server_name}__{tool_name}" 格式
    description: str
    input_model: type[BaseModel]  # 从 MCP input_schema 动态生成
    permission: str = "ask"       # MCP 工具默认需要确认
    is_concurrent_safe: bool = True

    async def execute(self, input: BaseModel) -> ToolResult:
        """通过 MCPClient.call_tool() 执行"""
```

#### DeferredToolRegistry

```python
@dataclass
class ToolIndex:
    name: str
    description: str

class DeferredToolRegistry:
    """管理延迟加载的工具索引。"""

    def register(self, tool_name: str, description: str) -> None:
        """添加工具到延迟索引。"""

    def promote(self, tool_names: set[str]) -> None:
        """将工具从延迟状态移除（下轮 LLM 可见完整 schema）。"""

    def is_deferred(self, tool_name: str) -> bool:
        """检查工具是否仍在延迟状态。"""

    def search(self, query: str) -> list[ToolIndex]:
        """搜索工具索引。
        支持三种查询：
        - "select:name1,name2" → 精确匹配
        - "+keyword rest" → name 包含 keyword，按 rest 排序
        - "keyword" → 正则匹配 name + description
        """

    def get_deferred_names(self) -> list[str]:
        """返回所有仍在延迟状态的工具名。"""

    def reset(self) -> None:
        """重置（新 session/请求时调用）。"""
```

#### tool_search 内建工具

```python
class ToolSearchTool(BaseTool):
    """内建工具：搜索延迟加载的工具索引，返回完整 schema。"""
    name = "tool_search"
    description = "Search available tools by keyword or exact name. Use 'select:name' for exact match."
    permission = "auto"  # 搜索操作无副作用，自动批准
    is_concurrent_safe = True

    async def execute(self, input: ToolSearchInput) -> ToolResult:
        """
        1. DeferredToolRegistry.search(query)
        2. 获取匹配工具的完整 schema（从 ToolRegistry）
        3. promote() 匹配的工具
        4. 返回 schema JSON
        """
```

### 2.3 LLM 调用时的 Schema 过滤

在 QueryLoop 的每轮 LLM 调用前：

```python
# 获取所有工具 schema
all_schemas = self._registry.get_schemas()

# 过滤掉仍在 deferred 状态的工具
if self._deferred_registry:
    visible_schemas = [
        s for s in all_schemas
        if not self._deferred_registry.is_deferred(s["name"])
    ]
else:
    visible_schemas = all_schemas

# system prompt 中注入 deferred 工具名单
deferred_names = self._deferred_registry.get_deferred_names()
if deferred_names:
    deferred_section = "<deferred-tools>\n" + "\n".join(deferred_names) + "\n</deferred-tools>"
    # 追加到 system prompt
```

### 2.4 安全设计

| 措施 | 说明 |
|------|------|
| 环境变量白名单 | MCPClient 子进程复用 BashTool 的 _safe_env() 模式，防止 API key 泄漏 |
| MCP 工具默认 ask | permission="ask"，用户未批准不执行 |
| 结果截断 | 复用 ToolExecutor 的 max_result_size |
| Server 名称前缀 | 工具名格式 "{server}__{tool}"，防命名冲突 |
| 子进程生命周期 | agent 关闭时自动 close 所有 MCPClient |

## 三、集成设计

### 3.1 QueryLoop 修改后的完整流程

```
1. 检查压缩阈值 → 可能压缩
2. PromptBuilder.build() 构建 system prompt
3. 注入 deferred tools 名单到 system prompt
4. 过滤 deferred 工具的 schema
5. HookManager.run_pre("pre_provider_call", event)
   → deny → 跳过 LLM 调用，构造 assistant 消息 "[Hook denied: {reason}]" 作为当轮响应，loop 继续下一轮
   → modify → 应用修改到 messages/system/tools（替换对应字段）
6. Provider.create()
7. HookManager.run_post("post_provider_call", event)
8. EventBus.emit(ProviderResponseEvent)
9. 累计 token 到 SessionState
10. 如果 stop_reason == tool_use:
    对每个 tool call:
      a. PermissionChecker 权限检查
      b. HookManager.run_pre("pre_tool_call", event)
         → deny → 返回 denied 结果，跳过执行
         → modify → 替换 input
      c. ToolExecutor.execute()（通过 BaseTool 或 MCPTool）
      d. HookManager.run_post("post_tool_call", event)
         → modify → 替换 result
      e. EventBus.emit(ToolResultEvent)
11. 如果 stop_reason == end_turn:
    MemoryManager.maybe_extract()
```

### 3.2 NeoAgent 构造变更

```python
class NeoAgent:
    def __init__(self, config, storage=None):
        ...
        self._hook_manager = HookManager()
        self._deferred_registry = DeferredToolRegistry()
        self._mcp_clients: dict[str, MCPClient] = {}

        # tool_search 自动注册（有 MCP server 时才激活）
        # hook/on/unhook 方法委托给 _hook_manager
        # add_mcp_server/remove_mcp_server 管理 _mcp_clients

    async def close(self) -> None:
        """关闭所有 MCP 连接。"""
        for client in self._mcp_clients.values():
            await client.close()
```

### 3.3 与 v3.1 现有系统的兼容性

| 现有系统 | 影响 |
|----------|------|
| EventBus | 不变，继续负责观察型事件 |

## 五、不做的事（显式排除）

- 不做 MCP Server 端（双向 MCP）
- 不做 SSE/HTTP 传输（只做 stdio，MCPTransport ABC 预留扩展）
- 不做 shell hook / 配置文件注册
- 不做 hook 持久化（hooks 是运行时注册，不存 session）
- 不做工具 schema 的持久缓存（每次连接重新获取）
- 不做 MCP OAuth（无远程传输场景）
- 不做 ContextVar 隔离（单进程单 session 场景，v3.2b Multi-Agent 时再加）
- 不改 EventBus 现有事件和 ObserverSubscriber
